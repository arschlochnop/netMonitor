# NetMonitor 需求设计

macOS 菜单栏工具：持续监控多条出口路径的公网 IP，校验其归属地 / 运营商是否符合预期，不符合时提醒。

> 状态：草案 v0.3。范围已确认，结论见文末“已确认的决定”。

## 1. 目标与典型场景

| 场景 | 说明 |
| --- | --- |
| 代理 / VPN 掉线 | 预期出口在日本，掉线后回落到本地宽带直连，需立刻知道 |
| 节点漂移 | 机场自动切换节点，出口从美国变成了香港，影响账号风控 |
| 分流验证 | 国内站点应走直连（看到国内 IP），海外站点应走代理（看到海外 IP），两条路都要对 |
| IPv6 泄漏 | IPv4 走了代理，但 IPv6 直连泄露了真实地址 |

**不做的事**：不负责建立 / 切换代理，不做流量统计、测速（可作为后续扩展）。

## 2. 核心概念

### 2.1 检测点（Probe）

本机的路由 / 分流规则会让访问不同国家网站的请求走不同出口，所以“多处出口”的含义是：**向多个位于不同国家的 IP 查询接口发请求，每个接口看到的出口 IP 可能不同，各自都要符合预期。**

一个检测点 = **查询目标 + 预期规则**。

```
检测点 ──┬── 查询目标：向哪个网站 / API 询问“我的 IP 是什么”
         └── 预期规则：这个网站看到的 IP 应该满足什么
```

| 检测点示例 | 查询目标所在 | 预期 |
| --- | --- | --- |
| 国内视角 | 国内的 IP 查询接口 | 国家 = CN（走直连） |
| 美国视角 | 美国的 IP 查询接口 | 国家 = US |
| 日本视角 | 日本的 IP 查询接口 | 国家 = JP，运营商不含某关键字 |

要点：

- **查询目标决定走哪条出口**，因此它是检测点的身份，不能随意换。回退用的备用接口必须与主接口命中同一条分流规则（通常即同一国家 / 同一域名分组），否则回退后测到的是另一条出口。
- **请求方式默认跟随系统**（系统路由 + 系统代理设置），与浏览器等日常应用的实际走向一致。
- 可选的“指定代理”（给单个检测点填 HTTP / SOCKS5 代理地址）列为 P1，用于本机代理未设为系统代理的情况。不支持指定网卡。

### 2.2 检测结果

每次检测产出一条记录：

| 字段 | 说明 |
| --- | --- |
| IP | IPv4 / IPv6 |
| 国家 / 地区 / 城市 | 国家用 ISO 3166‑1 二位码（`JP`、`US`） |
| ASN / 运营商 / 组织 | 如 `AS16509 Amazon.com` |
| IP 类型 | 住宅 / 机房 / 移动（查询接口支持时） |
| 原始响应 | 保留全文，供关键字匹配与排查 |
| 耗时、时间戳、使用的查询接口 | |

### 2.3 状态

每个检测点有四种状态，**“不符合”与“检测失败”必须区分**——断网不等于 IP 不对。

| 状态 | 含义 | 菜单栏表现 |
| --- | --- | --- |
| 正常 | 拿到 IP 且通过全部规则 | 绿 |
| 不符合 | 拿到 IP 但未通过规则 | 红，触发告警 |
| 检测失败 | 超时 / 查询接口不可用 / 断网 | 黄，默认不告警（可配置） |
| 已暂停 | 用户手动暂停 | 灰 |

## 3. 功能需求

优先级：**P0** = MVP 必须，**P1** = 首个正式版，**P2** = 后续。

### 3.1 检测点管理

- **P0** 增删改、启用 / 停用、排序；每个检测点有名称与可选的备注
- **P0** 保存前可“测试一次”，直接看到返回的 IP 与归属信息，方便写规则
- **P1** 复制检测点、导入 / 导出配置（JSON）
- **P1** 内置模板：“国内视角”“海外视角”“IPv6 泄漏检查”

### 3.2 IP 获取与归属地解析

- **P0** 内置一批公共查询接口，至少分**境内**、**境外**两组，建检测点时按组挑选；候选清单见 [endpoints.md](endpoints.md)
- **P0** 各接口的响应统一解析为相同字段（IP、国家码、地区、城市、ASN、运营商）；`ipip` 只返回中文国家名，需映射为二位国家码，映射不上时留空，仍可用关键字规则
- **P0** 支持自定义查询接口：URL + 响应格式（纯文本 IP / JSON 字段路径映射到 IP、国家、运营商等字段）
- **P0** 每个检测点可配备用接口，主接口失败时回退（须与主接口走同一出口，见 2.1）
- **P0** 接口只返回 IP 不返回归属地时，用一个统一的归属地解析服务补全（该请求走哪条出口不影响结果）
- **P0** IPv4、IPv6 可分别检测（分别请求仅 v4 / 仅 v6 的端点）
- **P1** 离线归属地库（MMDB 格式）：只从查询接口拿 IP，归属地本地解析，省配额、结果稳定
- **P1** 可选的多源一致性校验：两个库对同一 IP 的国家结论不一致时标注“归属存疑”
- **P1** 支持为查询接口填写 API Token（存 Keychain）

> 归属地库之间对同一 IP 的城市、甚至国家判断常有出入。**ASN / 运营商比城市可靠**，规则设计上应鼓励优先匹配国家码 + ASN。

### 3.3 预期规则

单条规则 = **字段 + 操作符 + 值**；一个检测点可配多条，用“全部满足 / 任一满足”组合。

| 字段 | 操作符 |
| --- | --- |
| 国家码 | 属于 / 不属于（多选） |
| 地区、城市、运营商、组织、ASN | 包含 / 不包含 / 等于 / 正则 |
| IP | 等于 / 属于 CIDR / 不属于 CIDR |
| IP 类型 | 等于（住宅 / 机房 / 移动） |
| 原始响应 | 包含 / 不包含 / 正则（兜底的“关键字”匹配） |

- **P0** 国家码属于 / 不属于、关键字包含 / 不包含（不区分大小写）、全部满足 / 任一满足
- **P1** 正则、CIDR、IP 类型
- **P1** “IP 变化即提醒”：不关心地区，只要出口 IP 与上次不同就通知（适合固定 IP 场景）
- **P2** 跨检测点规则：如“检测点 A 与 B 的 IP 必须不同”（验证分流生效）、“IPv6 检测点应当失败”（验证 v6 已禁用）

### 3.4 检测调度

- **P0** 定时：全局默认间隔（建议默认 60 秒），检测点可单独覆盖
- **P0** 手动：菜单内“立即检测全部”/ 单个检测
- **P0** 事件触发：网络变化（切 Wi‑Fi、VPN 网卡上下线）、系统唤醒后立即补测
- **P0** 请求超时（默认 8 秒）、并发执行各检测点
- **P1** 异常时自动加密检测频率，恢复后回落
- **P1** 电池供电 / 低电量模式下自动拉长间隔

### 3.5 告警与提醒

**触发与抑制**（避免切换节点瞬间的误报和刷屏）：

- **P0** 防抖：连续 N 次不符合才告警（默认 2）
- **P0** 状态变化才通知：正常→不符合 通知一次；持续不符合不重复
- **P0** 恢复通知：不符合→正常 时告知“已恢复”（可关）
- **P1** 持续异常的重复提醒间隔（默认每 10 分钟，可关）
- **P1** 静音：暂停提醒 15 分钟 / 1 小时 / 直到明天；可按检测点静音
- **P1** “检测失败”是否告警、连续多少次后告警，单独可配

**提醒方式**（可按检测点选择、可叠加）：

| 方式 | 优先级 | 说明 |
| --- | --- | --- |
| 菜单栏图标变色 | P0 | 始终生效，任一检测点异常即变红 |
| 系统通知 | P0 | 走通知中心，受“专注模式”影响 |
| 强提醒弹窗 | P0 | 置顶窗口，需手动关闭，不受专注模式影响 |
| 提示音 | P1 | |
| Webhook | P2 | 推送到 Bark / Telegram / 企业微信等 |
| 执行脚本 / 快捷指令 | P2 | 不符合时自动执行，如断开某应用网络（Kill Switch） |

通知内容需包含：检测点名称、当前 IP、实际归属、**具体是哪条规则没过**。

### 3.6 菜单栏界面

- **P0** 图标反映整体状态（全部正常 / 有异常 / 有失败 / 全部暂停）
- **P0** 下拉面板逐行展示检测点：状态点、名称、IP、国旗 + 国家 / 城市、运营商、上次检测时间
- **P0** 行内操作：复制 IP、立即检测、暂停
- **P0** 底部：立即检测全部、暂停全部、设置、退出
- **P1** 菜单栏文字可选显示指定检测点的国家码或 IP（如 `🇯🇵 JP`）
- **P1** 点开某行展开详情：完整归属信息、未通过的规则、最近变更

### 3.7 历史记录

- **P1** 记录每次 **IP 变化与状态变化**（而非每次检测，避免膨胀）
- **P1** 历史窗口：按检测点筛选，时间线展示“何时从哪个 IP / 地区变到哪个”
- **P1** 保留期限可配（默认 30 天），导出 CSV
- **P2** 可用率统计：近 24 小时 / 7 天的符合率

### 3.8 通用设置

- **P0** 开机自启、默认检测间隔、通知权限引导
- **P1** 中英文界面、日志查看与导出
- **P2** 自动更新

## 4. 非功能需求

- **资源占用**：常驻内存 < 50 MB，空闲时 CPU 接近 0；不显示 Dock 图标
- **隐私**：只向用户配置的查询接口发请求；无遥测、无账号；配置与历史全部本地存储
- **凭据安全**：代理密码、API Token 存 Keychain，不落明文配置文件
- **查询接口配额**：免费查询接口普遍限流，内置接口需标注限额，每个内置接口带“最小间隔”属性，检测点间隔不得低于它
- **健壮性**：单个检测点卡死不影响其他；查询接口返回异常格式时判为“检测失败”而非“不符合”
- **兼容性**：macOS 13+，Apple Silicon 与 Intel

## 5. 技术方案建议

| 方面 | 方案 | 备注 |
| --- | --- | --- |
| 语言 / UI | Swift + SwiftUI `MenuBarExtra` | 需 macOS 13+；`LSUIElement` 隐藏 Dock 图标 |
| 发起检测 | `URLSession` 默认配置，自动跟随系统路由与系统代理 | 禁用缓存与连接复用，避免切换节点后仍沿用旧连接得到旧结果 |
| 指定代理（P1） | 该检测点使用独立的 `URLSession` 并配置代理字典 | HTTP 与 SOCKS5 均可 |
| 网络变化监听 | `NWPathMonitor` | |
| 唤醒监听 | `NSWorkspace.didWakeNotification` | |
| 通知 | `UserNotifications` | |
| 开机自启 | `SMAppService` | |
| 存储 | 配置用 JSON 文件；历史用 SQLite | |
| 离线库 | MMDB 读取 | 库文件由用户自行下载导入，规避授权分发问题 |
| 分发 | 开源，GitHub Releases 提供构建产物，同时支持源码自行构建 | 不上架 App Store，不启用沙盒。无付费开发者账号时产物为未公证版本，README 需说明首次打开的放行步骤 |
| 许可证 | MIT | 依赖与内置资源需兼容；归属地库不随仓库分发 |
| CI | GitHub Actions 构建与发布 | |

**连接复用的注意点**：代理切换节点后，已建立的长连接可能继续走旧节点。每次检测必须新建连接，否则会出现“实际已漂移但检测仍显示正常”。

```json
{
  "defaultIntervalSeconds": 60,
  "probes": [
    {
      "name": "国内视角",
      "target": "builtin:cn-1",
      "fallbackTargets": ["builtin:cn-2"],
      "match": "all",
      "rules": [{ "field": "country", "op": "in", "value": ["CN"] }],
      "alert": { "debounce": 2, "channels": ["notification"] }
    },
    {
      "name": "日本视角",
      "target": {
        "url": "https://ip-api.example.jp/json",
        "format": "json",
        "fields": { "ip": "ip", "country": "country_code", "org": "org" }
      },
      "ipVersion": "v4",
      "match": "all",
      "rules": [
        { "field": "country", "op": "in", "value": ["JP"] },
        { "field": "org", "op": "notContains", "value": "China" }
      ],
      "alert": { "debounce": 2, "channels": ["notification", "popup"] }
    },
    {
      "name": "IPv6 泄漏检查",
      "target": "builtin:global-v6",
      "ipVersion": "v6",
      "match": "all",

      "alert": { "onFailure": "ignore" }
    }
  ]

```

## 7. 需要处理的边界情况

| 情况 | 处理 |
| --- | --- |
| 切换节点的瞬间短暂不符合 | 防抖（连续 N 次） |
| 完全断网 | 判“检测失败”，不按“不符合”告警 |
| 需网页认证的 Wi‑Fi | 查询接口返回登录页 HTML → 解析失败 → “检测失败” |
| 合盖休眠后唤醒 | 立即补测；唤醒后短暂宽限期内不告警，等网络恢复 |
| 查询接口被限流 / 宕机 | 回退到同出口的备用接口；全部失败才算“检测失败” |
| 查询接口域名被分流规则改动 | 用户调整代理规则后同一接口可能换了出口；检测点详情中展示实际请求的域名，便于对照规则排查 |
| 归属地库结果互相矛盾 | 标注“归属存疑”，由用户选择以哪个源为准 |
| 机器只有 IPv4 | IPv6 检测点失败是预期结果，可配置为不告警 |
| 首次启动未授权通知 | 引导授权；被拒绝时回退为弹窗 + 图标变色 |

## 8. 里程碑

**M1 — MVP（P0）**
菜单栏常驻；检测点 = 查询目标 + 规则，请求跟随系统；按国家分组的内置查询接口 + 自定义接口 + 回退；国家码与关键字规则；定时 + 手动 + 网络变化触发；防抖；系统通知 + 弹窗 + 图标变色；开机自启。

**M2 — 正式版（P1）**
单检测点指定代理；离线归属地库；正则 / CIDR / IP 变化规则；历史记录；静音与重复提醒；菜单栏文字显示；配置导入导出；中英文。

**M3 — 扩展（P2）**
Webhook；异常时执行脚本 / Kill Switch；跨检测点规则；可用率统计；自动更新。

## 9. 已确认的决定

| 问题 | 结论 |
| --- | --- |
| “多处出口”的含义 | 请求多个不同国家的网站 / API，因路由不同而得到不同出口 IP；每个查询目标是一个检测点 |
| 指定网卡 | 不做 |
| 最低系统版本 | macOS 13+ |
| 分发方式 | 自用 + 开源，不上架 App Store |
| 不符合时的自动动作 | 放到 M3 |

| 开源许可证 | MIT |
| 内置查询接口 | 搜集公共 API，至少境内、境外两组，见 [endpoints.md](endpoints.md) |

仍待办：IPv4 接口已实测一轮；IPv6 接口需在有 IPv6 的网络下重测；分流场景（代理开启时境内外接口出口不同）尚未实测。
